# Release runbook

How to ship a new version of `darwinvpn` to the Homebrew tap.

## TL;DR

```sh
# from a clean main branch
gh release create vX.Y.Z --generate-notes
```

That single command does three things:

1. Creates the `vX.Y.Z` tag on the current `HEAD` and pushes it to `origin`.
2. Publishes a GitHub Release whose notes are auto-generated from PR titles
   merged since the previous tag.
3. Triggers `.github/workflows/release.yml`, which runs GoReleaser on a macOS
   runner. GoReleaser cross-compiles `darwin/arm64` and `darwin/amd64`, uploads
   the tarballs and `checksums.txt` to the release, and pushes the regenerated
   Cask to `mrsmsn/homebrew-tap` at `Casks/darwinvpn.rb`.

Release notes generated by `gh release create --generate-notes` and by
GoReleaser (`changelog.use: github-native`) use the same GitHub API, so the two
match.

## Versioning

`vMAJOR.MINOR.PATCH`. Pre-release suffix (`-rc1`, `-beta.2`, …) is recognised:

- `.goreleaser.yaml: release.prerelease: auto` marks hyphen-bearing tags as
  GitHub pre-releases.
- `.goreleaser.yaml: homebrew_casks.skip_upload: auto` skips the tap commit on
  pre-releases, so the published `brew install` recipe always points at the
  latest stable tag.

Use `vX.Y.Z-rcN` for dry runs and `vX.Y.Z` for real releases.

## Full procedure

### 1. Pre-flight on `main`

```sh
git checkout main
git pull --ff-only
# CI must be green on origin/main
gh run list --branch main --workflow=ci.yml --limit 1
```

### 2. (Optional) Dry-run with a release candidate

```sh
gh release create vX.Y.Z-rc1 --generate-notes --prerelease
gh run watch "$(gh run list --workflow=release.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
```

Verify:

- `gh release view vX.Y.Z-rc1` lists three assets (`darwin_arm64`, `darwin_amd64`, `checksums.txt`).
- The tap repo (`mrsmsn/homebrew-tap`) is **not** updated — `skip_upload: auto`
  withholds RCs from the published install path.

### 3. Cut the real release

```sh
gh release create vX.Y.Z --generate-notes
gh run watch "$(gh run list --workflow=release.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
```

Verify:

- `gh release view vX.Y.Z` shows the three assets.
- `mrsmsn/homebrew-tap` has a new commit: `chore(cask): darwinvpn vX.Y.Z`.

### 4. End-to-end install check

```sh
brew uninstall --cask darwinvpn 2>/dev/null || true
brew untap mrsmsn/tap         2>/dev/null || true
brew install mrsmsn/tap/darwinvpn
darwinvpn version   # → darwinvpn vX.Y.Z
darwinvpn list      # exercises the private NetworkExtension path
```

## Rolling back

A release is rolled back by deleting the bad tag and pushing a follow-up patch.
Do **not** force-push tags — once a Homebrew user has installed `vX.Y.Z`, the
tarball under that tag must keep resolving.

```sh
# remove a broken release that no one has installed yet
gh release delete vX.Y.Z --cleanup-tag --yes
# in mrsmsn/homebrew-tap, revert the cask bump
git -C ../homebrew-tap revert <sha> && git -C ../homebrew-tap push
```

Otherwise, ship `vX.Y.(Z+1)` with the fix.

## Secrets and infrastructure

| Resource | Purpose | Location |
|----------|---------|----------|
| `HOMEBREW_TAP_GITHUB_TOKEN` | fine-grained PAT for pushing to `mrsmsn/homebrew-tap` (Contents R/W on that repo only) | `mrsmsn/darwinvpn` → Settings → Secrets and variables → Actions |
| `mrsmsn/homebrew-tap` | Homebrew tap that hosts the auto-generated `Casks/darwinvpn.rb` | Separate public repo |

The PAT expires at most yearly; rotation is the only recurring task and surfaces
as a red `release` workflow when stale.

## Why `gh release create` instead of `git tag && git push`

Both reach the same end state — GitHub fires a `tags/v*` event either way and
`release.yml` runs. The `gh` flow simply collapses three manual steps (tag,
push, create release with PR-based notes) into one command. Plain `git tag` is
still supported; the GoReleaser changelog stanza uses the same GitHub API as
`--generate-notes`, so the resulting notes are identical.
